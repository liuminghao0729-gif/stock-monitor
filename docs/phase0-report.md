# 阶段 0 报告:扩大使用范围前的底线检查(2026-11-22)

背景:网站已有 100 多人用过,计划继续小范围扩大,不完全公开。本阶段只读代码和公开条款,没有改任何功能。
说明:我不是律师。下面的"条款"来自网页搜索摘要,标注"未核实"的都需要你(或专业人士)读原文确认。

## 3. 隐私与安全检查

通过项:
- Supabase `user_data` 开启了行级权限,select/insert/update 都限定 `auth.uid() = user_id`。
- 管理密钥 `SUPABASE_SERVICE_KEY` 只出现在推送脚本和 GitHub Actions 的 secrets 里,没有进网页代码。
- 个人推送的日志只在试运行时打印,且聊天编号已打码(前 3 位 + ***)。
- 前端渲染外部文本时使用了 `esc()` 转义。

问题与建议:
1. **没有 delete 策略**:用户不能自己删除自己的数据。建议加 delete 策略,并在页面提供"删除我的数据"按钮。删除账号时有 `on delete cascade`。
2. **`/api/status` 返回 `SUPABASE_URL` 和 `SUPABASE_KEY`**:已核实(2026-11-22,读公开接口,只看类型)返回的是 publishable 公开密钥,安全。Vercel 里也确认没有设置 `SUPABASE_SERVICE_KEY`(用户确认)。该接口还返回各数据源是否配置和最近失败原因(`dbg`),建议精简。
3. **没有 vercel.json,也没有安全响应头**:缺 CSP、X-Frame-Options、Referrer-Policy 等。建议补上基础头(需要你确认后再部署)。
4. **仓库是公开的**(用户确认,2026-11-22)。我扫描了当前文件和全部 git 历史,没有发现疑似密钥(sk-、AIza、JWT、Telegram bot token、sb_ 开头密钥、api_key/token/password 赋值)或个人邮箱;提交者是 noreply 地址。注意这是模式扫描,不保证穷尽。公开仓库意味着:代码、选股规则、回测报告、`push/config.json`、工作流文件(含 secrets 的名字,不含值)、Actions 日志任何人都能看到。Actions 日志里只有试运行才打印个人摘要且聊天编号已打码,但试运行日志属于公开内容,以后不要在公开仓库跑带真实用户数据的试运行。是否改私有由你决定(会影响 Actions 免费时长和 Vercel 连接方式,我会先出方案)。
5. **隐私说明**:没有隐私页。建议写一页:收集什么(Google 邮箱、自选股、持仓、Telegram 编号)、用途、谁能读、如何删除。
6. **推送扩容**:`personal.py` 一次读取所有开启提醒的用户。人数增加后要测耗时与 Telegram 限速,放在阶段 3。
